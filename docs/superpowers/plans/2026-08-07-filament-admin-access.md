# Filament Admin Access Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install Filament and restrict the admin panel (`/admin`) to users with `is_admin = true`, per issue #15 (sub-issue 1/3 of #11).

**Architecture:** Install `filament/filament` and run its panel installer, which generates `App\Providers\Filament\AdminPanelProvider` registered in `bootstrap/providers.php` and wires the panel at `/admin`. Add an `is_admin` boolean column to `users` (default `false`). Implement `Filament\Models\Contracts\FilamentUser` on `App\Models\User` so `canAccessPanel()` gates access by that column. Seed a dedicated `admin@example.com` user with `is_admin = true`, separate from the existing `test@example.com` seed user. No Filament Resources (Course/Lesson/Material) are created in this plan — that's sub-issues #16 and #17.

**Tech Stack:** Laravel 13, Filament 4.x (installed fresh — check `composer.json` after `composer require` to confirm the resolved major version), PHPUnit-style feature tests (`Tests\TestCase` + `RefreshDatabase`, matching `tests/Feature/ExampleTest.php`).

## Global Constraints

- `is_admin` column: boolean, `default(false)`, on the existing `users` table (spec: `docs/superpowers/specs/2026-08-07-filament-admin-access-design.md`).
- Access control lives in `User::canAccessPanel()` — no allowlist, no roles package.
- Seeded admin user: `admin@example.com`, password `123456789`, `is_admin => true` — a **new** user, the existing `test@example.com` in `database/seeders/DatabaseSeeder.php` is untouched.
- Panel path stays the Filament default (`/admin`) — no custom panel ID or path.
- Full suite (`php artisan test`) must stay green when this task is done.

- [ ] **Step 8: Add `is_admin` to `User`'s fillable attributes**

Read `app/Models/User.php` first. It declares fillable fields via a PHP attribute, not a
`$fillable` property:

```php
#[Fillable(['name', 'email', 'password'])]
#[Hidden(['password', 'remember_token'])]
class User extends Authenticatable
```

`User::factory()->create(['is_admin' => true, ...])` mass-assigns through this list, so
`is_admin` must be added or the seeder silently drops it. Change the attribute to:

```php

```

// use Illuminate\Contracts\Auth\MustVerifyEmail;
use Database\Factories\UserFactory;
use Illuminate\Database\Eloquent\Attributes\Fillable;

Replace it with:

```php
<?php

namespace App\Models;

// use Illuminate\Contracts\Auth\MustVerifyEmail;
use Database\Factories\UserFactory;
use Filament\Models\Contracts\FilamentUser;
use Filament\Panel;
use Illuminate\Database\Eloquent\Attributes\Fillable;
use Illuminate\Database\Eloquent\Attributes\Hidden;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Relations\HasMany;
use Illuminate\Foundation\Auth\User as Authenticatable;
use Illuminate\Notifications\Notifiable;

#[Fillable(['name', 'email', 'password', 'is_admin'])]
#[Hidden(['password', 'remember_token'])]
class User extends Authenticatable implements FilamentUser
{
    /** @use HasFactory<UserFactory> */
    use HasFactory, Notifiable;

    /**
     * Get the attributes that should be cast.
     *
     * @return array<string, string>
     */
    protected function casts(): array
    {
        return [
            'email_verified_at' => 'datetime',
            'password' => 'hashed',
            'is_admin' => 'boolean',
        ];
    }

    public function lessonProgress(): HasMany
    {
        return $this->hasMany(LessonProgress::class);
    }

    public function canAccessPanel(Panel $panel): bool
    {
        return $this->is_admin;
    }
}
```
